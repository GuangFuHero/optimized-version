# 互助地圖（Mutual Aid Map）

> 原型：`Design/後台/互助地圖 Mutual Aid Map.html`
> 程式：`js/admin/map/*`、危險區樣式 `js/shared/wg-hazard.js`
> 正式版：`Frontend/apps/demo/src/app/admin/map/` ＋ `Frontend/libs/modules/src/map/`
> 正典：`MAP-FEAT-002` 責任區與危險區（AC-01〜AC-09、Q1〜Q6）；規則編號 `MAP-ZD-*` 見程式註解

## 這頁在做什麼

政府與平台管理者在地圖上**圈出區域**，告訴所有人「哪裡危險」「這一區交給誰」「這裡有什麼」。
責任區一圈下去，區內的任務單就一次指派給那個單位 —— 這是本頁最重要、也最危險的動作。

地圖上同時看得到：任務單（圖釘，顏色＝優先級）、資源站點、已圈的區域。

## 三種區域（🔒 2026-09-27 裁示）

| | 危險區 `hazard` | 責任區 `assign` | 標示區 `mark` |
|---|---|---|---|
| 用途 | 提醒大家不要進入 | 交給一個單位負責，區內任務單歸他 | 只標位置，不派單位 |
| 指派單位 | 不派 | **必填** | 不派 |
| 樣式（🔒 10-23） | 橘白斜紋（固定，`wg-hazard.js`） | **靛 #4338CA** | **綠 #15803D** |
| 前台可見（預設） | 開 | 關 | 關 |
| 例子 | 堤防潰口、土石流警戒 | 大平村交給慈濟基金會 | 志工休息區、集合點 |

- 🔒 危險區**不會自動到期**，要有人按「解除危險區」（2026-09-26，推翻 AC-06 的 24 小時）。
- 🔒 **2026-10-10 新裁示（原型尚未改）**：責任區只能公開；標示區可以純後台或純前台。原型目前仍是 09-27 的行為（三種都能勾「前台可見」）。
- 🔒 **區域顏色照類型固定（2026-10-23）**：後端 `work_zones` 沒有顏色欄位，所以**不存顏色、不給人選色**，前後台都呼叫 `js/shared/wg-hazard.js` 的 `wgZoneColor(kind)`。推翻原本的「每區輪替色」。兩色都避開任務單的優先級色與危險區的橘。已知代價：相鄰的責任區同色，靠邊線與名稱標籤分辨。

## 前台地圖上的區域（🔒 2026-10-23）

- **名稱標籤一直顯示**，內容是「類型・名稱」（`責任區・光復鄉 大平村`）。不只放在滑過才出現的提示裡 —— 前台多在手機上用，手機沒有滑過。
- 🔒 **標籤不可以蓋住區域本身**（`ZONE-LABEL-101`，`前台/js/site/site-map.jsx`）：休息區、集合點這種區域都很小，標籤放中央會把整塊蓋掉。每次縮放後量區域在畫面上的像素大小 —— 放得下標籤就置中，放不下就掛在區域**正下方**。❌ 不要用縮放級距寫死，區域大小差很多。
- 標籤壓在站點／任務標記底下（標記一定要點得到）。
- **點區域或點標籤**跳出：類型・名稱、🔄 **負責：單位**（只有責任區）、備註。
- 🔄 **責任區顯示負責單位**（2026-10-23 PM 裁示，照後端 ADR-311 10-11 修訂「責任區一經設立，前後台皆需公布被指派的組織名稱」；推翻 09-25 的不顯示）。

## 核心流程

**圈選新區域**（只有超級管理員與政府有這顆按鈕）

1. 按「圈選新區域」→ 在地圖上點出多邊形頂點。
2. 即時預覽：區內有幾張任務單、幾個站點（AC-02）。**超過 100 張**（`MAP_HIGH_VOLUME`）顯示高量警示。自我相交的形狀**不能送出**並說明原因（AC-08）。
3. 填資料：先選種類（三張卡片），再填名稱、說明、單位（責任區必填）、前台可見。
4. 可以**退回改範圍**，已填的資料不會消失。
5. 責任區送出前分項列出：未指派的、**已指派給別隊的**（AC-07 要警示，會被改掉）、已在本隊的。
6. 送出後 5 秒內可完整復原（AC-03，`MAP_UNDO_SECONDS`），復原也記進操作紀錄。

**編輯邊界**（🔒 正典 Q4，2026-08-27 裁示）

- 改大：新進入區內且**未指派**的單 → 指派給本區單位。
- 改小：掉出去、原屬本區單位的單 → **歸屬不動**，掛「待複核」（`reviewZoneId`），在區域詳情裡看得見、可清除。

**刪除／解除危險區**：🚨 刪除區域**不會**把任務單的歸屬收回（`MAP-ZD-147`，設計端定，未經裁示）。

**前台可見**：勾了的區域寫給前台地圖（`mapToPublicZone`）。🔄 責任區**帶負責單位** `team`（10-23，照 ADR-311）；不帶顏色（前台照類型算）；不帶區內任務單歸屬。

## 🔒 篩選是「看的方式」，不是「選的方式」（MAP-ZD-128）

區域的計數與批次指派**一律吃完整清單**，不吃篩選結果。
例：篩選只顯示「生命危急」，圈一個責任區 → 區內**所有**優先級的單都會被指派。
不這樣做，使用者會以為自己只指派了看得到的那幾張。這是最容易被「優化」掉的規則，**請不要改**。

## 權限

| 能力 | 超級管理員 | 政府 | 其他所有角色 |
|---|:-:|:-:|:-:|
| 看地圖、區域、操作紀錄 | ✅ | ✅ | ✅ |
| 圈選、編輯、指派、刪除、解除危險區、切前台可見 | ✅ | ✅ | — |

🔒 AC-01：未授權的人**不提供工具**（按鈕直接不 render），不是給一顆灰掉的按鈕。面板上會說明「圈選由超級管理員與政府執行」。

指派的單位清單：全部**啟用中**的團隊（政府＋非政府組織），依類型分組，政府在前（2026-09-25）。停權、已解散的隊不出現。

要實際看各角色的畫面：網址加 `?as=gov` 等，見 [角色與權限.md](角色與權限.md)。

## 資料形狀（原型）→ 後端對照

一筆區域：

```js
{ id, kind: "hazard" | "assign" | "mark", name,
  ring: [[lat, lng], ...],          // Leaflet 順序；送後端前轉 GeoJSON [lng, lat]
  team,                              // 責任區必填，其餘 null
  note, status: "active" | "expired",
  createdBy, createdAt,
  color,                             // 原型內部用；後端不存，一律 wgZoneColor(kind)
  publicVisible }                    // 🚨 欄位名是設計端取的
```

| 原型 | 後端（`main`） |
|---|---|
| 責任區／標示區的範圍 | ERD `work_zones(uuid, name, geometry MultiPolygon SRID 4326, created_by, …, delete_at)` |
| 責任區的單位 | ERD `team_zone_assign(team_uuid, zone_uuid)` |
| 危險區 | GraphQL `hazardousZones(bounds)`／`hazardousZone(uuid)`（`HazardousZoneType`：`name, geometry, status, informationSource, note`）—— **只有查詢，沒有 mutation** |
| 地圖上的任務單 | `tickets(bounds)`；本頁經 `mapBuildTickets()` 取 `TK_TICKETS` 中**有座標的**單（含前台報案） |
| 地圖上的站點 | `stations(bounds)`；本頁的 `MAP_STATIONS` 目前是空陣列，正式版與資源站點管理讀同一份 |

站點類型照抄正典 `libs/modules/src/station/type-options.ts`（11 值，`MAP_STATION_TYPES`）。⚠️ 不要自己加類型，前後台對不起來就是從各寫各的開始。

## 實作陷阱

- **篩選不影響指派**（見上）。
- 點在邊界上算「在區內」（`pointInPolygon` 刻意這樣寫）：災防寧可多框一張單，不要漏一張。
- 自我相交要在**畫的當下**就擋，不是送出時才報錯。
- 正典 AC-01 還要求矩形／圓形／自由曲線／點危害，原型**只做了多邊形**。
- 面積 `areaKm2` 是等距圓柱投影的粗算，只能拿來顯示，不能拿來做任何判斷。
- 原型每次載入會把「前台可見」區域整份寫回 `wg.bridge.publicZones`；頁面上沒有區域時會清空前台的標示區域圖層 —— 這是預期行為。
