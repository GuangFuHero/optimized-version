# 資源站點管理（Resource Station）

> 原型：`Design/後台/資源站點管理 Resource Station v2.html`
> 程式：`js/admin/station-v2/*`、外殼轉接 `js/admin/shell/station-shell.jsx`
> 正式版：`Frontend/apps/demo/src/app/admin/stations/` ＋ `Frontend/libs/modules/src/station/`
> 正典：`RS-FEAT-001`（本頁有多處刻意偏離，下文標 🚨／⚠️）

## 這頁在做什麼

災區裡的**固定地點**：避難收容、物資集散、醫療站、供水點、充電通訊……。後台人員在這裡維護「這個點還開著嗎、缺什麼、誰在管」，並審查民眾從前台送來的修改建議。

站點和任務單的差別：站點是「這裡**有**什麼」（長期存在）；任務單是「這裡**需要**什麼」（做完就結案）。站點的「久未更新」是資料新鮮度問題，**不是危險**，所以最多只到黃色，不用紅色。

## 核心規則

- 🔒 **營運狀態三態**：開設中 `open`／暫停服務 `paused`／已關閉 `closed`（2026-09-06；11-01 回 PR #232／#236 再確認），對後端 `active`／`temporarily_closed`／`permanently_closed`。暫停服務要寫一行原因（`pauseReason`）；跟開放時間無關。列表排序：開設中 → 暫停服務 → 已關閉。
- 🔒 **快速通道（AC-10）**：列表上直接切營運狀態，**立即生效、不進審查佇列**。其他欄位的修改都要走審查或抽屜編輯。
- 🔒 **CSV 匯入的站點：營運狀態用預設（開設中）、而且是官方**（2026-10-27 Carol：後台匯入理解為可信的來源）。推翻 2026-08-06「匯入後一律已關閉」與 2026-08-21「匯入 ≠ 官方造冊」。
- 🔒 **下架＝軟刪除**，只有超級管理員能做（AC-05）。下架的站點預設不出現在列表、計數也不算；超級管理員可在抽屜裡重新啟用。
- **新鮮度**：最後更新超過 24 小時＝灰色時鐘（hover 顯示「超過 24 小時未異動」）；超過 72 小時＝橘黃徽章。門檻在 `StationData.FRESHNESS`。
- **修改建議的衝突**：建議帶著送出當下的版本號 `baseVersion`。若站點之後已被改過（`baseVersion < version`）而且改到同一欄 → 該欄標衝突，必須「重新比對」才能核准。
- **站點群**（`type: "group"`）：大場地（例如糖廠）底下掛多個子站（`parentId`）。群本身**沒有**營運狀態與物資盤點，只是容器。篩選特定類型時，群會被濾掉、子站升到頂層並標「屬：○○」。🚨 正典沒有這個概念，見「待後端」。
- 版本歷史：每次寫入 `version + 1`，記一筆 `{ v, who, when, note, diff: [{ field, old, new }] }`。超級管理員可回滾。

## 資料形狀（原型）→ 後端對照

一筆站點（`StationData.STATIONS` 的元素）：

| 原型欄位 | 意義 | 後端 `StationType`（`schema.graphql`） |
|---|---|---|
| `id` | 站點編號 | `uuid` |
| `name` / `type` | 名稱、類型 | `name` / `type` |
| `address`, `lat`, `lng` | 地址、座標 | `secondaryLocation` / `geometry`（GeoJSON Point，**[lng, lat]**） |
| `area` | 行政區 | `secondaryLocation` 的行政區欄位 |
| `hours` | 開放時間 | `opHour` |
| `status` | 營運狀態 open/closed | ⚠️ **沒有** |
| `supplies: [{ item, level: full/low/out }]` | 物資盤點 | `properties`（站點動態欄位，由 `stationPropertyConfigs` 定義） |
| `contact`, `phone` | 聯絡人、電話（**僅後台可見**） | ⚠️ **沒有** |
| `photos` | 照片 | ⚠️ **沒有**（`photos.ref_type` 只有 ticket／pole） |
| `parentId` | 屬於哪個站點群 | ⚠️ ERD 有 `child_station_uuid`（命名相反，已請改名），GraphQL 沒暴露 |
| `assignedTeam` | 指派團隊 | ⚠️ **沒有** |
| `isOfficial`, `verified`, `verifiedBy` | 官方／已查核 | `isOfficial`、`verificationStatus` |
| `version`, `history` | 版本與歷史 | `audit_logs`（需另查） |
| `deleted` | 已下架 | 軟刪除 `delete_at` |
| `updatedMin` | 距最後更新分鐘數 | 由 `updatedAt` 算 |

一筆修改建議（`StationData.PROPOSALS`）：`{ id, stationId, stationName, submittedBy, submittedAt, source, baseVersion, status: pending/approved/rejected, statusOnly?, changes: [{ field, label, old, new, conflict? }] }`。

讀寫：`stations(bounds, stationType, skip, limit)`、`station(uuid)`、`createStation`、`updateStation`、`deleteStation`、`createStationProperty`／`updateStationProperty`、`upsertStationPropertyConfig`。

## 實作陷阱

- 快速通道和審查是**兩條不同的寫入路徑**，不要合併成一支「更新站點」就算了：前者不留待審紀錄、後者原資料在核准前不能變。
- NGO 角色的權限是**逐站判斷**（`canHandleStation`），不是整頁開關。同一個人在同一頁上，有的站能改、有的不能。
- 篩選站點類型時站點群會消失、子站升級 —— 這是刻意的，不是 bug（2026-08-21）。
- 地圖點擊＝新增站點，所以地圖上的空白狀態浮卡一定要 `pointer-events: none`，否則點不到地圖。
