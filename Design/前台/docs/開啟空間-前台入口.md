# 開啟空間：前台入口（2026-11-01）

> 給前端。規則編號 SPACE-FE-101〜104，同樣寫在程式碼註解裡（`js/site/site-map.jsx`、`site-building.jsx`、`site-list.jsx`）。
> 🔒 已裁示；🚨 設計端先定，可以提出異議。

## 問題

後台按「開啟空間」建好一棟（`createBuildingMap`）之後，前台**沒有任何地方看得到它**：

- 地圖原本只有「同一個地址已經有 2 張以上的單」才畫成一棟。剛開好的空間一定是 0 張單 → 永遠不出現 → 也就沒辦法在裡面開第一張單。
- 列表頁完全沒有空間的入口，只能從某一張單的詳情按「看各樓層」進去。
- 前台預設是**未登入**，原型原本只給已登入的人看空間 → 一般人打開前台什麼都看不到。

## 現在的行為

**後台開了空間 → 前台「任務」分頁的地圖與列表都會出現那一棟**，登入與否都看得到。

| | 已登入 | 未登入（訪客） |
|---|---|---|
| 地圖（任務分頁） | 建築標記：「N 件・缺 M」；沒有單時寫「看各樓層」 | 建築標記：一律「看各樓層」，**不顯示件數** |
| 列表（任務分頁最上面） | 「這些大樓可以看各樓層」一棟一列，寫件數與缺額 | 同一塊，一律「看各樓層」，不顯示件數 |
| 點下去 | 樓層抽屜（各層的單、每層「在這一層請求協助」） | 訪客版抽屜：**只有樓層按鈕**，選了直接進「請求協助」 |
| 在某一層請求協助 | 表單帶入這一棟與樓層，送出時帶 `buildingMapUuid` ＋ 樓層 | 走既有「登入後才能送出」（08-22 S-2：入口一律顯示，擋在送出前） |

## 規則

- 🔒 **SPACE-FE-101** 每一個開啟的空間都要在地圖上有標記，0 張、1 張也要。❌ 不要改回「2 張以上才畫」——空間的入口不能等到裡面已經有單才出現。「站點」分頁不畫（空間是放任務單的）。
- 🔒 **SPACE-FE-102** 整棟 0 張單時，抽屜多一句「這一棟還沒有人求助。點你所在的那一層，就能在那一層請求協助。」（各層預設收起，按鈕要展開才看得到）🚨 文案設計端定的
- 🔒 **SPACE-FE-103** 列表「任務」分頁最上面一塊「這些大樓可以看各樓層」：
  - 一棟一列：名稱、地址、件數／缺額，點了開同一個樓層抽屜
  - 跟著搜尋框走（比對名稱與地址）；**放在「沒有符合條件的資料」判斷外面**——搜尋某條街沒有任何單時，那棟樓仍要找得到
  - 不受子分類篩選影響（空間不是任務單）
  - 排序：缺人多的在前 → 有單的 → 還沒有求助的
  - 超過 3 棟先收起，給「看全部 N 棟」
  - 🚨 標題、3 棟、排序是設計端定的
- 🔒 **SPACE-FE-104** 訪客也看得到空間，但**不給任何件數或單**：
  - 訪客版抽屜不能沿用樓層清單——訪客拿到的單沒有樓層，每一層都會寫「尚無通報」，可是那一層可能有人在等。對訪客說「沒有」比不說更危險。
  - 沒有件數的標記壓在六邊形格子底下、整張卡放在點的上方，不能蓋住格子的「N 求助」（訪客唯一看得到的量）。
- 🔒 「缺 N」三處（地圖標記、列表、樓層抽屜）用**同一個算法**：只算人力／物資需求、不算搜救、不算已結案（09-20 規則，`summarizeList`）。原本地圖自己加總，同一棟地圖寫缺 16、抽屜加起來 12。

## 順手修的

- 從樓層開單時，戶／室沒有值會被存成字串 `"null"`，詳情顯示「3樓 null 室」→ 沒有就留空（`site-actions.jsx`）
- 表單上的地點卡印「3F 樓 室」（舊矩陣時代的「N 樓 M 室」寫法）→ 現在印「3F」
- 建築標記的報讀文字（title／aria-label）建立後不會更新 → 每次重畫都更新

## 請前端／後端確認

1. **訪客能不能讀 `buildingMaps(bbox)`？** 前台預設未登入，若這支 query 要登入，訪客就看不到空間。只需要名稱、地址、座標、樓層數，不需要底下的單。
2. 列表的那一塊需要「整份空間清單」，不是只有畫面範圍內的——空間數量應該不多，但請確認要用哪支 query。
3. 件數／缺額：原型是前端把這一棟的單撈回來自己算。正式版若單很多，請考慮由後端回聚合（同 10-24 訪客格子那題）。

## 怎麼看

1. 後台「任務管理」→「開啟空間」→ 放大頭針、填名稱與樓層 → 建立
2. 前台地圖切到「任務」：那一棟出現（「看各樓層」）；前台列表「任務」最上面也有
3. 點開 → 展開某一層 →「在這一層請求協助」→ 送出 → 標記變「1 件・缺 1」，詳情有「看各樓層」
4. 右上角登出，再看一次訪客版
