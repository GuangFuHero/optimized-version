## A. 帳號安全（PR #144）

### A1. 已定（🔒 照做）

| 項目 | 規則 |
|---|---|
| 用字 | 全部中文。「Email」→「電子郵件」；「綁定」→「完成新增」；「撤銷所有 refresh token，包含目前這個裝置」→「所有手機、電腦都會登出，包含這一台。」只有 LINE、Google 是品牌名不翻 |
| 字級 | 內文、欄位、按鈕 16px 起；按鈕高 48px |
| 區塊名稱 | 「設定登入密碼」「新增電子郵件或手機」「登出所有裝置」 |
| 新增電子郵件或手機的說明 | 「一次新增一個。為了安全，要先確認是你本人，再輸入新的電子郵件收到的驗證碼，共三步。」 |
| 電子郵件／手機二選一 | **分段選擇**：一個灰框兩格，選中的白底、粗字、前面打勾；上面一句「要新增哪一種？（選一個）」。❌ 不用兩顆按鈕（橘色實心那顆像「送出」）；❌ 不用開關 switch（那是開／關，不是二選一） |
| 步驟提示 | 點點＋文字「第 2 步，共 3 步」，下面接這一步的粗體標題。做完的點藍色、現在這步拉長、還沒到的灰色。三步的標題：「輸入新的電子郵件」「確認是你本人」「輸入新的電子郵件收到的驗證碼」（手機就把「電子郵件」換成「手機」） |
| 兩組驗證碼分得出來 | 第一組欄位叫「**原本的**電子郵件收到的驗證碼」，第二組叫「**新的**電子郵件收到的驗證碼」；兩組上方都寫寄到哪裡 |
| 有密碼的帳號，第 2 步 | 「為了確認是你本人，請先輸入你現在的密碼。」欄位「現在的密碼」，按鈕「確認」「取消」 |
| 沒有密碼的帳號，第 2 步 | 「為了確認是你本人，我們寄了一組驗證碼到你原本的電子郵件 w***@yahoo.com.tw。」按鈕「確認」「沒收到？重新寄一次」 |
| 第 3 步 | 「驗證碼已經寄到你新的電子郵件 wang@gmail.com。」按鈕「完成新增」「沒收到？重新寄一次」 |
| 只用 LINE、沒有聯絡方式 | 「為了確認是你本人，要先到 LINE 再登入一次。登入好會自動回到這裡。」按鈕「到 LINE 確認是我」 |
| 從 LINE 回來沒成功（橘色提示，不用紅色） | 按了取消：「你在 LINE 那邊按了取消，所以還沒新增。要再試一次，請按「寄驗證碼」。」／登入了別的 LINE：「你剛剛登入的 LINE 不是這個帳號用的那一個，請用原本的 LINE 再試一次。」／連不上：「現在連不上 LINE，請等一下再按「寄驗證碼」。」剛剛打的電子郵件要留著 |
| 只用 Google、沒有聯絡方式 | 兩個區塊的欄位**照樣出現但灰掉、不能輸入**，正下方一行說明（前面 ⓘ）：密碼區「你是用 Google 登入，又還沒有電子郵件或手機，所以暫時不能設定。」；聯絡方式區「你是用 Google 登入，暫時不能在這裡新增。」**不放按鈕**（灰掉的按鈕長輩會一直按） |
| 設定登入密碼的說明 | 「你現在是用 LINE 登入。設一組密碼，以後也可以用密碼登入。設好後要重新登入一次。」按鈕「設定密碼」 |

## B. 鈴鐺「求助單內容待確認」（PR #138）

### B1. 已定（🔒 照做）
- 圖示：警示三角形（TriangleAlert／ReportProblemRounded），**警示色、不用紅色**：單還在，只是內容可能有問題
- 點了打開那張單
- 字用「你」不用「您」（前台其他地方都是「你」）
- 給報名志工的內文：「你報名的求助單「XXX」資料可能有誤，出發前請先跟開單者確認。」

### B2. 待 Carol 決定（🚨）：給開單者的內文

背景：這是**資料檢核**（`ticket_audit.py`，PR #84），跟重複審核的合併無關。檢核員標「有問題」時一定要寫原因，但原因只給工作人員看；開單者點進去看不到哪裡有問題，前台也還不能改單。

| 方向 | 開單者看到 | 需要 |
|---|---|---|
| A 給原因 | 檢核員另外寫一句「給開單者看的原因」，通知內文和單的最上方都放這句 | 後端加欄位、後台加輸入框 |
| **B 不給原因（建議 V1）** | 「協調人員正在確認你的求助單「XXX」，有需要會跟你聯絡。」單的最上方放同一句 | 只改字 |

回覆前先照 **B** 做；前台可以改單之後再評估 A（V2）。
