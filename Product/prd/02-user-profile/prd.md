# Feature PRD — 個人檔案 (User Profile)

> **根基文件：** [`user-stories.md`](user-stories.md)（角色、情境、使用者目標——請先讀這份）
> **關聯文件：** `research/in-app-notification-patterns.md`、[user-journey.md](../../user-journey.md)

---

## 核心概念：輕量通知 + 個人化記憶

本功能由兩塊組成：

* **通知中心**：採「**非主動推播、開頁時更新**」的輕量模型——不做即時推播，靠頁面載入與輕量輪詢更新未讀數。設計目標是「不錯過重要事件」而非「即時轟炸」。
* **個人化偏好**：記住使用者常用的圖層與觀測站點，存於後端、跨裝置一致。

---

## 使用者情境

* **角色：** 所有後台管理人員（Super Admin、Government、NGO、Data Auditor）
* **場景：** 使用者登入後台後查看個人資訊、確認角色身份，或了解是否有待處理的通知（任務配對、審查結果等）。
* **痛點 / 觸發點：** 後台人員在災害應變期間高頻使用系統，若需主動查找通知、或不清楚自己的角色與聯絡資訊，會造成應變效率低落。

---

## IDEAL Case

1. 使用者打開後台頁面，系統在載入時自動更新通知徽章，顯示未讀數。
2. 點擊通知區，清楚看到「任務已有人承接」「修改建議已審查完成」「角色升等已通過」等條目，點擊即跳到對應頁面。
3. 進入個人檔案頁，一目了然看到姓名、電話、Email 與目前後台角色。
4. 系統記住常用的 Pin 圖層與觀測站點，下次進入地圖頁自動套用。
5. **結果：** 不需重複設定，個人化工作環境讓上手加快，通知機制確保不錯過重要事件。

---

## User Story

* As a **任務發起者**，I want **當志工承接我的任務時收到通知**，so that **我知道任務已被跟進，不需要主動追蹤**。
* As a **前台使用者**，I want **知道自己提交的資料修改建議審查結果**，so that **確認平台資訊是否已被更正**。
* As a **後台管理人員**，I want **系統記住我常用的圖層與觀測站點**，so that **每次登入不需要重新設定工作環境**。

---

## 功能需求

### F1. 通知中心

#### F1.1 通知類型
* **任務配對提醒**：有志工承接任務時，任務發起者收到通知。
* **審查結果通知**：前台使用者提出的資料修改建議審查結果。
* **角色升等提醒**：前台使用者申請變更為後台權限之通過通知。

> 通知範圍是否擴及緊急公告、Zone 指派 / Hazard 警示、待審佇列徽章，見開放問題。

#### F1.2 更新機制（傳輸）
* **兩段式**：頁面載入先拉一次「未讀數」；停留期間以**輕量輪詢只拉計數**，點開鈴鐺才拉清單內容（仿 GitHub）。
* **輪詢間隔**：平時 **60 秒**、**災害啟動期間自動縮短至 15–30 秒**（與 [[09-emergency-announcement]] 即時性對齊）；各 client 加 ±10–20% 隨機抖動（jitter）避免驚群打爆後端。
* **支援瀏覽器**：Safari、Chrome 等核心瀏覽器。

#### F1.3 已讀模型（三態）

| 狀態 | 含義 | 觸發 |
|------|------|------|
| `unseen` | 計入鈴鐺紅點數字 | 新通知產生 |
| `unread` | 列表內粗體，但細節未看 | 打開鈴鐺（紅點清除，**不**自動全標已讀） |
| `read` | 已點開該則 | 點進通知 |

* 提供「全部標為已讀」批次操作；已讀狀態存後端、跨裝置同步。

#### F1.4 分組、保留與歷史
* **分組**：可依三種類型篩選；同一 Ticket / 同一申請的多則更新聚合為一條。
* **保留**：站內通知保留 **90 天**，逾期歸檔 / 清除（長期稽核由 [[05-member-management]] 的 Audit Log 承擔，非靠通知）。
* **歷史頁**：鈴鐺快覽（最近 N 則）與「全部通知」完整頁分離。

#### F1.5 防洗版
* **任務配對提醒**：同一 Ticket 短時間多人承接 → **合併**為一則含計數（「您的任務有 3 則新進度」）。
* **審查結果 / 角色升等**：一次性結果，**不合併**，每則保留。

#### F1.6 通知跳轉（Deep Link）

| 通知類型 | 跳轉目的地 |
|---|---|
| 任務配對提醒 | 該 Ticket 詳情抽屜（[[08-ticket-management]]） |
| 審查結果通知 | 該資源站 / 建議結果頁（[[07-resource-station]]） |
| 角色升等提醒 | 個人檔案角色區，重新整理套用新權限（[[05-member-management]]） |

### F2. 基本資訊（User Info）

| 欄位 | 必填 |
|------|------|
| 名字 | 是 |
| 暱稱 | 否（選填） |
| 電話 | 是 |
| Email | 是 |
| 後台角色身份 | 是（系統指派） |

### F3. 系統使用習慣（個人化偏好）

* 記錄：常固定（Pin）的圖層、常 Pin 的觀測站點、習慣關注的任務類型。
* **持久化**：偏好存於後端 `user_preferences`（非僅瀏覽器 localStorage），確保換裝置一致；結構 `{ pinned_layers[], pinned_stations[], watched_task_types[] }`。
* **失效處理**：Pin 的目標若日後失效（圖層被刪、觀測站被刪），**保留 ID 但渲染時略過失效項**，避免報錯。

## 驗收標準

- [ ] 使用者開啟任意頁面時，通知徽章自動更新，無須手動刷新。
- [ ] 通知列表清楚區分三種通知類型，每條顯示事件摘要與時間戳記。
- [ ] 個人資訊頁完整顯示名字、電話、Email 與後台角色身份。
- [ ] 使用者 Pin 的圖層與觀測站點在下次登入後自動套用。
- [ ] Safari 與 Chrome 瀏覽器均能正常顯示通知。
- [ ] 打開鈴鐺只清除紅點（unseen→seen），不會把每則自動標為已讀。
- [ ] 同一 Ticket 短時間多次承接的通知會合併為一則含計數。
- [ ] 每類通知點擊後跳轉至對應目的地（deep link）。
- [ ] Pin 偏好存於後端、換裝置一致；失效項渲染時自動略過不報錯。
- [ ] 輪詢間隔平時 60 秒、災害期 15–30 秒，並帶隨機抖動。
