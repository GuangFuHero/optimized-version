## 使用者情境

* **角色：** 所有後台管理人員；前台使用者申請角色升等
* **場景：** 使用者需要更新聯絡方式（換手機號碼）、重設忘記的密碼，或申請角色升等（例如從一般志工申請成為後台 Data Auditor）。
* **痛點 / 觸發點：** 若無明確的申請入口，角色升等流程會依賴口頭溝通或非正式渠道，難以追蹤與審核，導致權限混亂。

---

## IDEAL Case

1. 使用者進入設定頁，清楚看到「帳號安全」、「聯繫資訊」、「角色申請」三個分區。
2. 忘記密碼：輸入 Email 或電話，30 秒內收到重設連結或驗證碼。
3. 申請角色升等：填寫申請原因後送出，系統顯示「申請已送出，等待 Super Admin 審核」。
4. 申請通過後，使用者收到通知（見 [[02-user-profile]]），重新登入後介面自動更新為新角色的權限。
5. **結果：** 所有帳號自助操作都有清楚的反饋狀態，不依賴線下溝通。

---

## User Story

* As a **後台管理人員**，I want **自助重設忘記的密碼**，so that **不需要聯繫管理員即可恢復存取**。
* As a **前台使用者**，I want **提交角色升等申請並追蹤審核狀態**，so that **我知道申請進度而不需要主動詢問**。
* As a **後台管理人員**，I want **更新我的電話號碼與 Email**，so that **平台能透過正確的聯絡方式通知我**。

### 帳號安全

## 安全與生命週期拆細（v1.1）

> 詳見 [`research/account-security-lifecycle-patterns.md`](research/account-security-lifecycle-patterns.md)。模糊處標 🟡 建議，未推翻 v1.0。

### S1. 密碼相關

* **忘記密碼**：
  * 入口輸入 Email 或手機；**防枚舉**——無論帳號是否存在皆回「若帳號存在已寄出重設連結」（與 [[01-auth]] 一致）。
  * 🟡 建議：重設連結有效期 **30 分鐘**、簡訊碼 **5 分鐘**，一次性且僅最新一封有效。
  * 重設成功後**登出其他所有 session** 並寄「密碼已變更」通知。
* **變更密碼（已登入）**：要求輸入舊密碼（或近期 step-up 重新驗證）；改完同樣登出其他 session + 通知。
* 🟡 **待確認**：社群登入 / SSO 帳號**沒有平台密碼**——「變更密碼」對 Google / Line / 究平安 SSO 帳號應隱藏或導向原 provider 修改。

### S2. 敏感識別資料變更（Email / 手機）

> 只驗「新的」是帳號接管高風險點。業界共識是「驗新 + 通知舊 + 變更前 step-up」三件套。

* **驗新的**：對新 Email / 手機寄 OTP / 確認連結，確認確實持有後才生效。
* **通知舊的**：對舊 Email / 手機寄「聯絡方式正被變更，若非本人請撤銷」通知。
* **變更前 step-up**：近期未驗證者，變更前要求重新輸入密碼 / OTP。
* 🟡 建議：**改暱稱屬非敏感**，不需 OTP（沿用 v1.0）；24h 撤回冷靜期列為 v2 可選。

### S3. 角色升等申請狀態機（對齊 [[05-member-management]] F5）

```
draft → submitted → under_review → approved
                               └→ rejected(附理由) → (冷卻後可重送)
submitted/under_review → withdrawn(使用者主動撤回)
```

* **審核者分流**：加入特定 Team → 該 **Team Admin** 審；平台角色（Government / Data Auditor）→ **Super Admin** 審。
* 🟡 **約束建議**：同類型已有 pending 申請時不可重複送出；審核前可主動撤回；被拒後可重送但建議 24h 冷卻或要求補充理由。
* **進度可視**：設定頁顯示目前狀態與時間軸；每次狀態轉移透過 [[02-user-profile]] 站內通知告知。

### S4. 帳號停用 / 刪除（釐清語義）

> v1.0 寫「帳號停用（自行申請停用）」——這是使用者**自助**操作，對應「可逆休眠（Deactivate）」，**不是刪除**，也不同於 [[05-member-management]] 管理者端的 suspend（停權）。

* **自助停用＝可逆休眠**：登出全部 session、不再收通知；重新登入即恢復（或顯示「重新啟用」）。
* 🟡 **約束建議**：若該使用者為某 Team 的唯一 Admin，須先指派接班才能停用（與 [[05-member-management]] E1 一致）；最後一位 Super Admin 不可自助停用（與 E8 一致）。
* 🟡 **待確認（刪除權）**：是否提供個資法/GDPR 意義的「帳號刪除」？建議 **30 天寬限期 + 軟刪除**，期間可撤回、期滿匿名化。

### S5. 異常場景（v1.1 新增）

| 編號 | 場景 | 處理建議 |
|------|------|----------|
| **U1** | SSO / 社群登入帳號嘗試「變更密碼」 | 隱藏該項或導向原 provider。 |
| **U2** | 變更 Email 後新信箱也無法收信 / 填錯 | 變更未驗證前**不生效**，舊信箱仍有效，可重新發起。 |
| **U3** | 重複送出相同升等申請 | ⛔ 阻擋：已有 pending 申請時提示「已有待審申請」。 |
| **U4** | 申請被拒後立即連續重送 | 🟡 建議冷卻期 24h 或要求補充理由。 |
| **U5** | Team 唯一 Admin / 最後一位 Super Admin 自助停用 | ⛔ 阻擋：須先指派接班（對齊 05 之 E1 / E8）。 |
| **U6** | 停用後又想回來 | 重新登入自動恢復休眠帳號，原資料與 Team 歸屬保留。 |

## 成功驗收標準

- [ ] 忘記密碼流程完成後，使用者可在 5 分鐘內透過 Email 或 SMS 完成密碼重設。
- [ ] 角色升等申請送出後，系統顯示待審狀態，使用者可在個人頁看到申請進度。
- [ ] 申請通過或拒絕後，使用者收到站內通知。
- [ ] 聯繫資訊（電話、Email）修改後需經過驗證（OTP 或確認信）才生效。
- [ ] 帳號停用操作須有二次確認步驟，防止誤觸。
- [ ] 密碼重設 / 變更成功後，其他裝置 session 全部失效並發出變更通知。
- [ ] 變更 Email / 手機時同時驗證「新的」並通知「舊的」，未驗證前不生效。
- [ ] 升等申請有完整狀態（待審 / 通過 / 拒絕 / 撤回），重複申請被阻擋。
- [ ] 自助停用為可逆休眠，重新登入可恢復；唯一 Admin / 最後 Super Admin 不可直接停用。
