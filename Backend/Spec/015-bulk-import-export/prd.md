## 1. 問題

資源站點管理列表右上角的「匯入」「匯出」按鈕只是前端 stub。後台人員要大量更新站點資訊（例如災後統一更新營業時間），或把外部名冊匯進系統時，只能一筆一筆在 UI 改。

困難在於站點和求助單都有**依型別而不同的動態欄位**，不是單純的欄位對欄位。

## 2. 使用者

| 角色 | 能做什麼 |
|---|---|
| super_admin | 匯出、匯入全部 |
| data_auditor | 匯出全部，**不能**匯入 |
| team admin | 匯出自己 WorkZone 內的資料；匯入時新增不限區域，更新只限自己區域 |
| team member / 一般使用者 | 都不能 |

## 3. 使用者故事

### US-1 匯出成範本（P1）

身為後台人員，我想把某一種站點（例如避難所）匯出成 Excel，改完再匯回去。

**驗收條件**
1. **Given** 選了 `station_type=shelter`、`format=xlsx`，**When** 匯出，**Then** 下載一份檔案：固定欄位在前、`uuid` 在第一欄，動態欄位以 `prop.` 開頭在後。
2. **Given** 該型別已設定欄位但還沒有任何資料，**Then** 仍然匯出只有表頭的空範本。
3. **Given** 手機欄位，**Then** Excel 打開時前導 0 不會被吃掉；CSV 帶 BOM，中文不亂碼。
4. **Given** 站名以 `=` 開頭，**Then** 打開檔案時**不會**被當成公式執行（ADR-208）。
5. **Given** 呼叫者沒有該筆求助單的 PII 權限，**Then** 那一列的聯絡資料是遮蔽的，同一份檔的其他列不受影響。
6. **Given** 符合條件的資料超過 10,000 列，**Then** 回 400，並說明要縮小範圍；**不會**給出被截斷的檔案（ADR-239）。
7. **Given** 型別不存在或格式不是 csv/xlsx，**Then** 回 400。

### US-2 匯入前預覽（P1）

身為後台人員，我想在寫入前先看到「會新增幾筆、會更新幾筆、哪些列有問題」。

**驗收條件**
1. **When** 上傳檔案到 preview，**Then** 回傳偵測到的表頭、建議的欄位對應、配不上的欄位、前 20 列、預計新增數、預計更新數、**全部**的錯誤列，而且資料庫完全沒被寫入。
2. **Given** 原封不動匯出的檔案，**When** 預覽，**Then** 零錯誤、零新增。
3. **Given** 某個站點動態欄位的型別存不下（非 Integer），**Then** 列在 `skipped_columns` 並附原因（ADR-118）。
4. **Given** 比對到兩筆以上既有資料，**Then** 該列錯誤只說「比對到 N 筆」，**不透露**是哪幾筆（ADR-210）。
5. **Given** 檔案超過 500 列或 2 MB，或 xlsx 解壓後超過 32 MB，**Then** 在解析之前就回 400。

### US-3 執行匯入（P1）

**驗收條件**
1. **Given** 比對鍵對到恰好一筆，**Then** 更新那一筆；空白儲存格保留原值。
2. **Given** 比對不到，**Then** 新增，且座標必填。
3. **Given** 一列失敗，**Then** 只有那一列失敗，其他列照常寫入（ADR-213）。
4. **When** 匯入完成，**Then** 回傳新增數、更新數、失敗數、逐列錯誤，並附上**錯誤報表**（原本的列 + 一欄錯誤原因，格式與上傳的相同，base64 內嵌）。
5. **Given** 修正錯誤報表後重新上傳，**Then** 可以直接匯入；即使原檔本來就有一欄叫 `error` 也不會衝突（ADR-242）。
6. **Given** 某列的主資料寫入了、後續步驟才失敗，**Then** 列號出現在 `partial_rows`。
7. **Given** 同一份檔匯入兩次，**Then** 第二次什麼都不會改變。

### US-4 PII 保護（P2）

**驗收條件**
1. **Given** zone 權限的團隊成員匯出 100 列，其中 30 列在區域外（電話被遮蔽），**When** 原檔匯回，**Then** 那 30 列失敗，原因寫明「沒有這筆的 PII 權限，不能匯回」，**不會**被當成新增而產生重複單。

## 4. 功能需求

- **FR-001**：匯出必須指定單一型別，欄位順序固定，這份檔同時是匯入範本。
- **FR-002**：比對鍵：站點 = 名稱 + 縣市 + 區；求助單 = 標題 + 聯絡電話；任務 = 所屬求助單 + 任務型別 + 任務名稱。
- **FR-003**：比對鍵欄位與建立後就不能改的欄位，在更新列上一律忽略（ADR-108）。
- **FR-004**：檔案內有兩列同鍵時，那幾列全部失敗；但一張求助單底下的多個任務除外（ADR-120/211）。
- **FR-005**：匯入的動態欄位值必須依欄位設定驗證（未定義、Enum 不在選項內、型別錯都算失敗）。這條只在匯入路徑生效（ADR-117）。
- **FR-006**：有長度上限的欄位要在寫入前檢查（ADR-241）。
- **FR-007**：匯入需要 `*.import`，而且新增列還要 `*.add`、更新列還要 `*.edit`。preview 本身也要 `*.import`。
- **FR-008**：伺服器不保存匯入狀態，preview 和 commit 各自上傳同一份檔（ADR-114）。
- **FR-009**：動態欄位表的變更必須留下稽核紀錄。

## 5. 前端契約

| 端點 | 成功 | 失敗 |
|---|---|---|
| `GET /bulk/stations/export?station_type=&format=` | 檔案下載（`Content-Disposition` 依 RFC 6266 編碼） | 400 型別未知 / 格式不支援 / 超過 10,000 列；403 無權限 |
| `GET /bulk/tickets/export?task_type=&format=` | 同上 | 同上 |
| `POST /bulk/{stations,tickets}/import/preview`（multipart：`file`、選填 `mapping` JSON） | `BulkPreviewResponse` | 400 檔案無法解析 / 超過上限 / mapping 不合法；403 |
| `POST /bulk/{stations,tickets}/import/commit`（同上） | `BulkImportResponse` | 同上 |

⚠️ 這組端點的 400 目前**只有 `detail` 字串，沒有 `code`**（auth 端點已走 #41 的錯誤碼合約）。見 §8 待決 1。

錯誤列格式：`{ line: 試算表列號（表頭是第 1 列）, column: 欄位名或 "-", message }`
錯誤報表：`{ filename, media_type, content_base64 }`，前端解碼後讓使用者下載。

**建議的 UI 流程**：選型別 → 上傳 → 預覽（顯示錯誤、確認欄位對應）→ 使用者改檔重傳，或確認 → commit → 顯示結果並提供錯誤報表下載。

## 6. 範圍外

- AI 重複偵測（ADR-113）
- 修正站點動態欄位只能存 Integer 的既有缺陷（ADR-118）
- 非同步 / 背景匯入（ADR-114）
- 匯入歷史頁、整批回退、在稽核紀錄中圈出「某一次匯入」（ADR-124）
- `.md` / `.json` 格式（ADR-115）
- 匯出分頁或更多篩選條件（ADR-239 記錄的後續票）

## 7. 成功指標

- **SC-001**：「匯出 → 不修改 → 匯入」零錯誤、零新增、零變更。
- **SC-002**：500 列的檔案可以在單次同步請求內完成預覽和匯入。
- **SC-003**：任何單列資料問題，最多只讓那一列失敗，不會讓整份檔 500。
