# PRD：帳號資料自助維護（012 Account Profile）

**Feature**：012-account-profile　**PR**：#39（併入 #45 一起合併）
**Status**：後端已實作；前端表單未做（ADR-237：前端不進本 PR）
**Notion**：系統性 - Account Profile 設定（姓名/電話/信箱）+ 忘記密碼
**技術設計**：`spec.md`　**決策**：`decisions.md`（ADR-085~089、098、159~166、215~216、224~232）
**相關**：017 登入方式強化（ADR-220 改寫了本票「新增聯絡方式」的規則）

## 1. 問題

使用者無法自己維護帳號資料：
- 換了手機或信箱，系統改不動（已有同型別就 409）。
- 看不到自己目前綁了哪些聯絡方式、哪些登入方式。
- 刪不掉不再使用的聯絡方式。

聯絡方式同時是**登入帳號**和**忘記密碼的收件處**，所以「改聯絡方式」本身就是帳號接管的入口。這個功能要在「自助」和「不被偷帳號」之間取得平衡。

## 2. 使用者

| 角色 | 情境 |
|---|---|
| 一般使用者（有密碼） | 換了手機號碼，要改成新的 |
| SSO-only 使用者（只用 Google/LINE 登入） | 想補一個 email，或換掉舊的 |
| 帳號擁有者（受害者視角） | 有人拿到了他的 session，他需要被通知、而且帳號不能被偷走 |

## 3. 使用者故事

### US-1 更換聯絡方式（P1）

身為使用者，我想把舊手機換成新手機，而且換的過程中不會有「帳號沒有任何聯絡方式」的空窗。

**為什麼是 P1**：換號碼是最常見的需求，也是目前完全做不到的事。

**驗收條件**
1. **Given** 有密碼的帳號已有手機，**When** 送出新手機號碼但沒帶密碼，**Then** 回 422 `step_up_required`，而且新號碼**收不到**任何驗證碼。
2. **Given** 同上，**When** 帶正確密碼送出，**Then** 新號碼收到 6 位數驗證碼；驗證後舊號碼被取代。
3. **Given** 帶錯密碼，**When** 送出，**Then** 回 401 `step_up_invalid`。
4. **Given** SSO-only 帳號，**When** 送出新值，**Then** 驗證碼寄到**舊的**聯絡方式，要輸入那組碼才能繼續。
5. **Given** 取代成功，**Then** 舊管道收到「聯絡方式已變更為 a\*\*\*@\*\*\*.com」的遮蔽通知；帳號其他還在的管道也收到通知（ADR-229）。
6. **Given** 取代成功，**Then** 新值可以登入、舊值不行；其他裝置的登入**不會**被踢掉。

### US-2 新增另一種聯絡方式（P1）

身為只有手機的使用者，我想補一個 email，之後也能用 email 登入和收重設密碼信。

**驗收條件**（**依 017 ADR-220 修訂**，原本「首次新增不需驗證」已作廢）
1. **Given** 帳號有密碼，**When** 新增第一個 email，**Then** 需要輸入密碼（422 → 帶 `step_up.password` 重送）。
2. **Given** 帳號沒密碼、但有其他聯絡方式，**When** 新增，**Then** 驗證碼寄到**既有的**管道（剛加入未滿 7 天的管道不算，ADR-219）。
3. **Given** 帳號只有 SSO、沒有聯絡方式也沒有密碼，**When** 新增，**Then** 要出示自己那個 SSO 的新 `id_token`（ADR-234）。
4. **Given** 新增成功，**Then** 帳號既有的管道收到通知（ADR-224）。

### US-3 刪除聯絡方式（P2）

身為使用者，我想刪掉不再使用的聯絡方式，但系統不能讓我把自己鎖在門外。

**驗收條件**
1. **Given** 只剩一個聯絡方式、也沒有 SSO，**When** 刪除，**Then** 回 409 `last_login_channel`，而且**不需要**先輸入密碼（先檢查守門，再要求驗證）。
2. **Given** 還有其他登入方式，**When** 刪除但沒帶驗證，**Then** 回 422 `step_up_required`。
3. **Given** 帶正確驗證，**When** 刪除，**Then** 回 204，剩下的管道收到遮蔽通知；如果一個都不剩（靠 SSO 登入），通知寄到被刪的那個。
4. **Given** 刪除一個自己沒有的型別，**Then** 回 404。
5. **Given** 兩個刪除請求同時送出，**Then** 帳號不會被清到沒有登入方式（ADR-163）。

### US-4 查看自己的聯絡與登入方式（P2）

**驗收條件**
1. **When** 呼叫 `GET /users/me`，**Then** 回傳 `contacts[]`（明碼，看自己的不遮蔽）與 `login_methods[]`。
2. **Then** `login_methods` 只有 `provider`，**絕不**包含 `provider_subject`。

### US-5 SSO-only 帳號第一次設定密碼（P3）

**驗收條件**（ADR-215）
1. **When** 只憑 session 呼叫 `set-password`，**Then** 回 422，驗證碼寄到帳號既有的聯絡方式。
2. **When** 帶碼設定，**Then** 回 204、所有 session 被撤銷、每個聯絡方式都收到「已設定密碼」通知。
3. **Given** 帳號沒有任何聯絡方式，**Then** 回 422 `no_proof_channel`，提示先新增聯絡方式。

## 4. 功能需求

- **FR-001**：系統必須允許使用者以「驗證新值 → 同交易取代」的方式更換 email / 手機。
- **FR-002**：任何會新增、取代、刪除聯絡方式，或設定第一組密碼的操作，都必須先出示帳號擁有權證明；證明種類由**後端**依帳號狀態決定。
- **FR-003**：證明優先順序：密碼 → 已滿 7 天的聯絡方式收碼 → 帳號自己的 SSO token。
- **FR-004**：帳號必須永遠保有至少一個可登入的方式。
- **FR-005**：每次聯絡方式或密碼變動成功後，必須通知帳號其他管道，且新值要遮蔽。
- **FR-006**：通知寄送失敗不得讓變更回滾（ADR-162）。
- **FR-007**：更換聯絡方式**不**撤銷 session；設定第一組密碼**要**撤銷。
- **FR-008**：驗證碼只能用在它被發出的那個動作和目標（ADR-164）。
- **FR-009**：驗證碼寄送有每帳號次數上限，已經有效的碼不重發（ADR-165）。

## 5. 前端契約（錯誤碼）

所有錯誤都帶 `code`（#41 的合約），前端依 `code` 分流，**不要比對訊息字串**。

| 端點 | HTTP | `code` | 前端應該做什麼 |
|---|---|---|---|
| `POST /auth/contacts` | 202 | — | 顯示「驗證碼已寄出」 |
| | 422 | `step_up_required` | 顯示證明欄位（密碼 / 舊管道驗證碼 / SSO 重新驗證），填完同一顆按鈕重送 |
| | 401 | `step_up_invalid` | 「密碼或驗證碼錯誤」 |
| | 409 | `identifier_taken` | 「這個信箱/手機已被其他帳號使用」 |
| | 422 | `identifier_invalid` | 欄位格式錯誤 |
| `POST /auth/contacts/verify` | 400 | `code_invalid` | 「驗證碼錯誤或過期」 |
| `DELETE /auth/contacts/{type}` | 409 | `last_login_channel` | 「帳號至少要保留一個登入方式」，**不要**顯示證明欄位 |
| | 404 | `no_proof_channel` | ⚠️ 見 §8 待決 1 |
| `POST /auth/contacts/resend` | 404 | `no_pending_contact` | 「沒有等待驗證的變更，請重新送出」 |
| `POST /auth/set-password` | 409 | `password_already_set` | 導去改密碼 |
| | 422 | `no_proof_channel` | 「請先新增一個聯絡方式」 |

`step_up` 的欄位：`password`（前端先雜湊，與 change-password 相同）、`old_channel_code`、`id_token`。

## 6. 範圍外

- 同型別多筆聯絡方式（公務與私人信箱都能登入）— ADR-098
- 忘記密碼流程本身（已完整實作，本票不改）
- 更換聯絡方式後撤銷 session — ADR-085
- 帳號刪除 / 停用
- 前端表單（ADR-237；另開前端票）

## 7. 成功指標

- **SC-001**：只持有被竊 session 的攻擊者，無法透過聯絡方式或密碼相關端點取得帳號（012 + 017 的接管鏈測試全部通過）。
- **SC-002**：使用者換手機後，除了輸入密碼或驗證碼，不需要聯絡管理員。
- **SC-003**：每一次聯絡方式或密碼變動，擁有者至少有一個變更前就存在的管道收到通知。
