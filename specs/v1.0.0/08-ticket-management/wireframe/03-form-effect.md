## 已停用欄位的舊資料

水災退了、Super Admin 停用「積水深度」。打開一張水災期間的舊工單：

```
┌──────────────────────────────────────────────────────────────┐
│  後台 › 工單 #d0000042                                        │
├──────────────────────────────────────────────────────────────┤
│  受困人數 *  ┌──────┐                                        │
│              │ 2    │                                        │
│              └──────┘                                        │
│  樓層        ┌──────┐                                        │
│              │ 1    │                                        │
│              └──────┘                                        │
│                                                              │
│  ── 已停用欄位 ──────────────────────────────────────────    │
│  積水深度    80 公分                              🔒 唯讀     │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

**資料不會消失、也不會變成看不見的孤兒**——這是 D15「可停用不可刪除」換來的。

> 原本這裡有一整段關於「欄位被移除後舊資料變孤兒」的疑慮。該疑慮建立在「欄位清單跨應變沿用」的假設上；實際上**一場應變結束後資料庫即關閉、不沿用到下一場**，加上 D15 只停用不刪除，此問題不成立。

## 直立救援怎麼落地

舊設計的三道閘門（災害含直立救援 ∧ 後台代報 ∧ 樓層≠1F → 轉必填），在新模型下：

| 舊閘門 | 現在怎麼做 |
|---|---|
| 閘1 災害是否含此欄位 | 由「欄位有沒有被加進清單」決定——加開地震時，結構評估欄位隨欄位組進來 |
| 閘2 民眾端永不必填 | 維持。自訂欄位完全不出現在前台（D4） |
| 閘3 樓層≠1F 轉必填 | **廢止**。改為填了非 1 樓時顯示「建議補齊結構評估」提示，不擋儲存（D16） |

## 還沒設計的東西

欄位清單目前缺這些，都直接影響上面的表單。**多數是工程實作，已列入 PRD 開放問題。**

| 缺什麼 | 沒有的話會怎樣 | 屬性 |
|---|---|---|
| **必填標記** | 沒辦法要求「救援一定要填受困人數」 | 已拍板要做（D13），schema 待補 |
| **顯示名稱** | 現在只有代號 `people_count`，畫面上的中文沒地方存 | 工程 |
| **排序** | 欄位順序無法控制，資料庫回什麼順序就什麼順序 | 工程 |
| **停用旗標** | D15 的停用沒有欄位可存 | 工程 |
| **驗證規則** | 只能限定下拉選項，無法限制「樓層 1～50」 | 工程 |
| **欄位級權限** | 無法設定「危害備註不給訪客看」，需銜接 `[[10-guest-ticket-privacy]]` | 產品＋工程 |
| **異動紀錄** | Super Admin 停用一個欄位沒有軌跡 | 工程 |
