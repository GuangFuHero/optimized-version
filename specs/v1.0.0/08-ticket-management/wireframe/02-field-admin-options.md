# 02 — 管理員自訂欄位的三個做法

**情境：** 水災來了，現場需要記「積水深度」。系統現在沒有這個欄位。管理員打開後台，看到什麼、能點什麼？

三個做法差在**管理員被允許動的層級**。

---

## 做法 A — 需求種類鎖死，只開放欄位

管理員只能往現成的種類底下加欄位。要開新種類得工程加。

```
┌─────────────────────────────────────────────────────────────┐
│  後台 › 欄位設定                                             │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│   ┌─────────┬─────────┬─────────┐                           │
│   │ 救援 ▊  │  人力   │  物資   │   ← 固定三個，不能改       │
│   └─────────┴─────────┴─────────┘                           │
│                                                             │
│   救援類需求的欄位                                           │
│   ┌───────────────────────────────────────────────────┐     │
│   │  ⠿  受困人數        整數                    ⋯     │     │
│   │  ⠿  樓層            整數                    ⋯     │     │
│   │  ⠿  門牌號          文字                    ⋯     │     │
│   │  ⠿  危害備註        文字                    ⋯     │     │
│   └───────────────────────────────────────────────────┘     │
│                                                             │
│   [ + 新增欄位 ]                                            │
│                                                             │
└─────────────────────────────────────────────────────────────┘

           點「新增欄位」↓

┌─────────────────────────────────────────────────────────────┐
│  新增欄位到「救援」                                    ✕     │
├─────────────────────────────────────────────────────────────┤
│   欄位名稱   ┌──────────────────────────┐                   │
│              │ 積水深度                  │                   │
│              └──────────────────────────┘                   │
│   型別       ( ) 文字   (•) 數字   ( ) 單選   ( ) 是/否      │
│   單位       ┌──────────┐                                   │
│              │ 公分      │                                   │
│              └──────────┘                                   │
│                                                             │
│                              [ 取消 ]    [ 新增 ]           │
└─────────────────────────────────────────────────────────────┘
```

**結果：** 「積水深度」加在「救援」底下。**地震時也會看到它。**

因為平台一次只做一場應變，所以做法 A 的心智模型是：
**欄位清單 = 這場應變的表單設定，開新災害時整理一次。**

---

## 做法 B — 種類也開放新增

管理員可以先開一個新種類，再往下掛欄位。

```
┌─────────────────────────────────────────────────────────────┐
│  後台 › 欄位設定                                             │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│   ┌─────────┬─────────┬─────────┬──────────┬─────────┐      │
│   │  救援   │  人力   │  物資   │ 抽水 ▊   │  ＋     │      │
│   └─────────┴─────────┴─────────┴──────────┴─────────┘      │
│                                    ↑ 管理員自己開的          │
│   抽水類需求的欄位                                           │
│   ┌───────────────────────────────────────────────────┐     │
│   │  ⠿  積水深度        數字 (公分)             ⋯     │     │
│   │  ⠿  抽水機數量      整數                    ⋯     │     │
│   └───────────────────────────────────────────────────┘     │
│                                                             │
│   [ + 新增欄位 ]                                            │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

**結果：** 分類最貼合現場，但**跨災害統計會碎掉**——這次叫「抽水」、下次有人開「排水」，事後想問「歷年抽水需求總量」就對不起來。

---

## 做法 C — 多加一個「災害」維度

同一個種類，在不同災害底下顯示不同欄位。

```
┌─────────────────────────────────────────────────────────────┐
│  後台 › 欄位設定                                             │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│   災害  ┌──────────┐                                        │
│         │ 水災   ▾ │   ← 先選災害                           │
│         └──────────┘                                        │
│                                                             │
│   ┌─────────┬─────────┬─────────┐                           │
│   │ 救援 ▊  │  人力   │  物資   │                           │
│   └─────────┴─────────┴─────────┘                           │
│                                                             │
│   水災 × 救援 的欄位                                         │
│   ┌───────────────────────────────────────────────────┐     │
│   │  ⠿  受困人數      整數           〔所有災害共用〕  │     │
│   │  ⠿  樓層          整數           〔所有災害共用〕  │     │
│   │  ⠿  積水深度      數字 (公分)    〔只在水災〕      │     │
│   └───────────────────────────────────────────────────┘     │
│                                                             │
│   [ + 新增欄位 ]                                            │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

**結果：** 水災看得到積水深度、地震看不到，最精準。

**但代價：** 這跟先前「災害移到平台層、Ticket 不帶災害」的決定有張力。而且平台一次只做一場應變——既然當下只有一場災害，「先選災害」這個動作在多數時候是多餘的。

---

## 三者對照

|  | A 只開欄位 | B 種類也開 | C 加災害維度 |
|---|---|---|---|
| 管理員能做的 | 加欄位 | 加種類＋加欄位 | 依災害加欄位 |
| 水災欄位會不會污染地震 | 會 | 不會 | 不會 |
| 跨災害統計 | 可統計 | 會碎掉 | 可統計 |
| 需要改資料庫 | 否，現況就支援 | 否，現況就支援 | **是**，要加欄位 |
| 跟「災害在平台層」是否衝突 | 否 | 否 | 有張力 |
| 管理員的心智負擔 | 低 | 中 | 高（多一層） |

## 我的建議

**做法 A。** 三個理由：

1. **現在就能動**，不必改資料庫。B 也不用改，但 A 的分類不會長歪。
2. **平台一次只做一場應變**——這是既有決定。既然當下只有一場災害，「欄位清單」本來就等於「這場應變的設定」，不需要再切一個災害維度。開新應變時整理一次欄位即可。
3. C 想解的問題（水災欄位污染地震）在 A 底下是**用流程解而不是用結構解**：換災害時整理欄位清單。少一層結構、少一半的維護成本。

**但 A 有一個真實代價要你知道：** 如果欄位清單會隨每場應變改動，那**上一場災害留下的舊資料**，它的欄位可能已經不在清單裡了。舊工單打開會看到「積水深度：80」但系統已經不認得這個欄位。這要決定怎麼處理（保留顯示為唯讀？隱藏？），我列進開放問題。
