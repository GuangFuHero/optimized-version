# 02 — 欄位設定（已拍板）

**做法 A+：需求種類固定、欄位開放、災害欄位組作為預設集。** 決策與理由見 [`../decisions.md`](../decisions.md) D10–D16。

限 Super Admin 操作（D14）。

## 加開災害 → 欄位自動加入

```
┌────────────────────────────────────────────────┐
│  加開災害種類                             ✕    │
├────────────────────────────────────────────────┤
│   ○ 火災        ● 水災        ○ 土石流         │
│   ○ 颱風        ○ 毒化災                       │
│                                                │
│   套用「水災」會加入這些欄位：                   │
│   ┌──────────────────────────────────────┐     │
│   │ 救援 › 積水深度      數字 (公分)      │     │
│   │ 救援 › 是否斷電      是/否            │     │
│   │ 人力 › 需要抽水機    整數             │     │
│   │ 物資 › 需要沙包      整數             │     │
│   └──────────────────────────────────────┘     │
│                                                │
│   ⓘ 之後關閉水災時，這些欄位不會自動移除        │
│                                                │
│                       [ 取消 ]   [ 加開水災 ]  │
└────────────────────────────────────────────────┘
```

**欄位組是「哪個需求種類 × 哪個欄位」的配對集合**，不是單純一串欄位名（D11）——因為欄位本來就掛在需求種類底下。

組的內容由工程預先定義、隨系統出貨，管理員只能整組套用，不能編輯組內容。

## 關閉災害

```
┌────────────────────────────────────────────────┐
│  關閉「水災」                             ✕    │
├────────────────────────────────────────────────┤
│   水災不再列為當前應變的災害種類。               │
│   影響統計維度與地圖圖層。                       │
│                                                │
│   ☐ 一併停用水災組帶進來的 4 個欄位             │
│     └ 預設不勾。停用後新表單不顯示，            │
│       已填的資料仍看得到。                      │
│                                                │
│                       [ 取消 ]   [ 關閉水災 ]  │
└────────────────────────────────────────────────┘
```

**預設不動欄位**（D10 只加不減），但給一鍵選項免得逐個關（D15）。

## 新增欄位 — 先搜尋欄位庫

```
┌────────────────────────────────────────────────┐
│  新增欄位到「救援」                       ✕    │
├────────────────────────────────────────────────┤
│   ┌──────────────────────────────────────┐     │
│   │ 🔍 淹水                               │     │
│   └──────────────────────────────────────┘     │
│                                                │
│   系統欄位庫找到：                              │
│   ┌──────────────────────────────────────┐     │
│   │ ▸ 積水深度    數字 (公分)   〔水災組〕 │     │
│   │ ▸ 淹水面積    數字 (平方公尺)         │     │
│   └──────────────────────────────────────┘     │
│                                                │
│   ─────────────  或  ─────────────             │
│                                                │
│   找不到適合的？  [ 自訂新欄位 ]                │
│                                                │
└────────────────────────────────────────────────┘
```

**先搜尋、找不到才自訂（D12）。** 這是自動整併能成立的唯一前提——從欄位庫挑的欄位共用同一個識別，所以後續套用水災組時系統認得出「這個已經有了」，不會重複加入，已填的資料也不用搬。

自訂的欄位在**本場應變內與欄位庫欄位完全平等**（可篩選、可設必填、可統計），只是不會自動回到欄位庫；用得好可事後由工程升格收進欄位庫（D13）。

## 沒有被選上的做法

| 做法 | 為什麼不採用 |
|---|---|
| **需求種類也開放新增** | 分類會長歪。而且需求種類影響志工承接的篩選與媒合，不只是分類標籤。 |
| **加一個「災害」維度** | 一場應變結束資料庫即關閉、不沿用下一場，所以不需要用結構隔離不同災害。多這一層只是增加維護成本與心智負擔。 |
